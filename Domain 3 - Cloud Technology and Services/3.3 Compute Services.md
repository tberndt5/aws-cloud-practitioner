# 3.3 Identify AWS compute services

> [!abstract] Exam guide objective (verbatim from the CLF-C02 exam guide)
> **Knowledge of:**
> - AWS compute services
>
> **Skills in:**
> - Recognizing the appropriate use of different EC2 instance types (for example, compute optimized, storage optimized)
> - Recognizing the appropriate use of different container options (for example, Amazon ECS, Amazon EKS)
> - Recognizing the appropriate use of different serverless compute options (for example, AWS Fargate, Lambda)
> - Recognizing that auto scaling provides elasticity
> - Identifying the purposes of load balancers

## Big picture

Compute is where your code runs, and AWS offers a spectrum from full control to fully managed: virtual servers (EC2), containers (ECS, EKS, with or without Fargate), functions (Lambda), and simplified or specialized platforms (Elastic Beanstalk, Lightsail, Batch). The exam gives a workload description and asks which option fits, so learn the cue words: "full control of the OS" is EC2, "Kubernetes" is EKS, "run containers without managing servers" is Fargate, "run code in response to events" is Lambda. Two supporting ideas round out the objective: **Auto Scaling provides elasticity** (capacity follows demand) and **load balancers distribute traffic** across healthy targets in multiple AZs.

## Key concepts

### Amazon EC2 (Elastic Compute Cloud)

EC2 "provides scalable computing capacity in the AWS Cloud": virtual servers called **instances** that you launch in minutes and pay for while they run. It is IaaS, so ==you manage the guest OS, patches, and software== on it ([[2.1 Shared Responsibility Model]]).

- **AMI (Amazon Machine Image):** the template an instance boots from: OS, preinstalled software, and configuration. Sources: AWS-provided, AWS Marketplace, community, or your own custom AMI (create once, launch many identical instances). AMIs are Regional; you can copy one to another Region.
- **Instance type:** the hardware profile (vCPU, memory, storage, network), named like `m7g.large` (family `m`, generation `7`, attribute `g` for Graviton, size `large`).
- **Storage:** EBS volumes (persistent network block storage) or instance store (temporary, lost when the instance stops). See [[3.6 Storage Services]].
- **Pricing:** On-Demand, Reserved Instances, Spot, Savings Plans, Dedicated Hosts/Instances belong to Domain 4: see [[4.1 AWS Pricing Models]] and [[EC2 Purchasing Options]].

### EC2 instance families

| Family | Optimized for | Example use cases | Letters to recognize |
| --- | --- | --- | --- |
| **General purpose** | Balance of compute, memory, networking | Web servers, code repositories, small and mid-size databases, dev/test | M, T (burstable), Mac |
| **Compute optimized** | High-performance processors | ==Batch processing, media transcoding, high-performance web servers, scientific modeling, dedicated game servers, ML inference== | C |
| **Memory optimized** | Large data sets in memory | ==In-memory databases and caches, real-time big data analytics==, large enterprise apps (SAP HANA) | R, X, z |
| **Storage optimized** | High, low-latency sequential read/write to large **local** storage | ==High-throughput databases (OLTP, NoSQL), data warehousing, distributed file systems, log processing== | I, D, H |
| **Accelerated computing** | Hardware accelerators (GPUs, custom chips, FPGAs) | ML training, graphics rendering, floating-point calculations, video processing | P, G, Inf, Trn, F |

Exam cue: "lots of CPU" = compute optimized; "large data set in RAM" = memory optimized; "high IOPS on local disks" = storage optimized; "GPU" = accelerated computing; "balanced or unknown" = general purpose.

Current status: AWS's instance types page now also lists a sixth category, **HPC optimized** (Hpc family), for large-scale simulations. The exam guide does not name it.

### Containers: ECS, EKS, ECR, Fargate

A **container** packages an application with everything it needs to run, so it behaves the same everywhere. Docker is the common format; **Kubernetes** is a popular open-source system for running containers at scale.

| Service | What it is | Choose it when |
| --- | --- | --- |
| **Amazon ECS** (Elastic Container Service) | AWS's own container orchestrator: "deploy, manage, and scale containerized applications" | You want the simplest AWS-native way to run Docker containers |
| **Amazon EKS** (Elastic Kubernetes Service) | Managed **Kubernetes**: "run Kubernetes without the need to install, operate, or maintain the Kubernetes control plane or nodes" | The team already uses Kubernetes, wants portability with on-premises or other clouds |
| **Amazon ECR** (Elastic Container Registry) | "Container image registry that is secure, scalable, and reliable" | You need somewhere to **store** container images (it does not run them) |
| **AWS Fargate** | Serverless compute engine for containers: no EC2 instances to manage | You want containers without provisioning, patching, or scaling servers |

ECS and EKS each have two **launch options**: run containers on EC2 instances you manage (more control, can use Reserved or Spot pricing) or on **Fargate** (AWS manages the servers; you pay per vCPU and memory used by the task). The reference guide says Fargate "works with Amazon ECS"; it also works with Amazon EKS.

### Serverless compute: Lambda vs Fargate

**Serverless** means no servers to provision or manage, automatic scaling, built-in availability, and paying only for what you use.

| | AWS Lambda | AWS Fargate |
| --- | --- | --- |
| Unit | A **function** (your code) | A **container** (task or pod) |
| Runs | In response to **events** (S3 upload, API Gateway request, DynamoDB stream, schedule) | Continuously or as tasks, under ECS or EKS |
| Duration | Short: ==maximum 15 minutes per invocation== | No such limit; long-running services fine |
| Billing | Per request and per millisecond of duration (by memory size) | Per second of vCPU and memory requested |
| Cue | "run code without servers", "event-driven", "trigger" | "containers without managing servers or clusters" |

Lambda: "run code without the need to provision or manage servers." AWS patches the Lambda OS; you own the code ([[2.1 Shared Responsibility Model]]).

### Other compute services

| Service | Reference guide summary | Signal words |
| --- | --- | --- |
| **AWS Elastic Beanstalk** | "Deploy and manage applications without knowledge of the underlying infrastructure" | Upload web-app code; AWS handles capacity, load balancing, scaling, health monitoring. PaaS; no extra charge. |
| **Amazon Lightsail** | "Launch projects quickly from a simple management interface" | Simple virtual private servers with **predictable low monthly price** bundling compute, storage, and data transfer; small websites, WordPress, beginners. |
| **AWS Batch** | "Run batch computing workloads" | Hundreds of thousands of batch jobs; Batch plans, schedules, and provisions compute (EC2, Spot, Fargate) for you. |
| **AWS Outposts / Local Zones / Wavelength** | Compute closer to users or on premises | See [[3.2 AWS Global Infrastructure]]. |

### Auto Scaling provides elasticity

**Elasticity** is the ability to acquire resources when you need them and release them when you don't, so capacity tracks demand (Domain 1: [[1.1 Benefits of the AWS Cloud]]). **Scalability** is the ability to grow; elasticity adds automatic shrinking.

- **Amazon EC2 Auto Scaling** manages an **Auto Scaling group** of EC2 instances with a **minimum**, **desired**, and **maximum** size. It launches instances when a metric (for example CPU from CloudWatch) crosses a threshold, terminates them when demand falls, and replaces unhealthy instances (which also improves availability). Policies: dynamic (target tracking, step), scheduled, and predictive.
- **AWS Auto Scaling** "monitors applications to automatically scale resources dynamically by adjusting capacity based on defined thresholds." It manages scaling **across multiple services** from one place with scaling plans: EC2 Auto Scaling groups, Spot Fleets, ECS tasks, DynamoDB table capacity, and Aurora read replicas.
- **Horizontal scaling** (scale out/in: add or remove instances) is what Auto Scaling does. **Vertical scaling** (scale up/down: bigger or smaller instance) needs a resize.

Auto Scaling has no extra charge; you pay for the resources and CloudWatch monitoring.

### Elastic Load Balancing (ELB)

A **load balancer** "automatically distributes your incoming traffic across multiple targets, such as EC2 instances, containers, and IP addresses, in one or more Availability Zones." It runs **health checks** and sends traffic only to healthy targets, and it scales itself automatically. Paired with Auto Scaling across multiple AZs, it is the standard high-availability pattern.

| Type | Layer | What it is for |
| --- | --- | --- |
| **Application Load Balancer (ALB)** | Layer 7 (HTTP/HTTPS) | Web applications; routes by URL path, host name, or headers; microservices and containers; integrates with AWS WAF |
| **Network Load Balancer (NLB)** | Layer 4 (TCP/UDP/TLS) | Extreme performance, millions of requests per second, ultra-low latency, static IP per AZ; gaming, IoT, non-HTTP protocols |
| **Gateway Load Balancer (GWLB)** | Layer 3 (IP packets) | Deploying and scaling **third-party virtual network appliances** such as firewalls and intrusion detection/prevention systems |
| Classic Load Balancer | Layers 4 and 7 | Previous generation; AWS recommends migrating |

AWS patches and manages the load balancers themselves ("patch ELBs" is an AWS responsibility in the reference guide).

## Exam traps and commonly confused

> [!warning] ECS vs EKS
> Both orchestrate containers. **EKS = Kubernetes.** If the question doesn't mention Kubernetes, ECS is usually the simpler answer.

> [!warning] ECR vs ECS
> ECR **stores** images (registry). ECS **runs** containers. One letter apart, very different jobs.

> [!warning] Fargate vs Lambda
> Fargate runs **containers** with no time limit. Lambda runs **functions** triggered by events, up to **15 minutes**. Long-running process or existing container image: Fargate. Short event-driven code: Lambda.

> [!warning] Fargate vs ECS/EKS
> Fargate is not an orchestrator; it is the serverless **compute** that ECS or EKS places containers on.

> [!warning] Elastic Beanstalk vs Lightsail vs CloudFormation
> Beanstalk: deploy *your code* on managed AWS infrastructure. Lightsail: simple bundled servers at a *fixed monthly price*. CloudFormation: *templates* for any infrastructure.

> [!warning] Compute optimized vs memory optimized vs storage optimized
> CPU-bound (transcoding, batch, HPC, gaming servers) = compute. Large in-memory data (in-memory databases, real-time analytics) = memory. Heavy local disk I/O (NoSQL, data warehouse, distributed file systems) = storage.

> [!warning] Auto Scaling vs load balancing
> Auto Scaling changes **how many** instances run. A load balancer decides **which** instance receives each request. They are used together.

> [!warning] ALB vs NLB vs GWLB
> HTTP routing by path = ALB. TCP/UDP, extreme performance, static IP = NLB. Third-party firewall appliances = GWLB.

## Quick self-check

> [!question]- Which EC2 instance family fits a video transcoding farm?
> Compute optimized.

> [!question]- Which EC2 instance family fits a large in-memory database?
> Memory optimized.

> [!question]- Which EC2 instance family fits a NoSQL database that needs very high random I/O on local disks?
> Storage optimized.

> [!question]- What is an AMI?
> Amazon Machine Image: the template (OS, software, configuration) used to launch EC2 instances.

> [!question]- A team runs Kubernetes on premises and wants a managed equivalent on AWS. Which service?
> Amazon EKS.

> [!question]- Where do you store Docker images for ECS or EKS?
> Amazon ECR.

> [!question]- Which service runs code in response to an S3 upload without any servers to manage?
> AWS Lambda.

> [!question]- What is the maximum run time of a single Lambda invocation?
> 15 minutes.

> [!question]- What gives an application elasticity by adding EC2 instances under load and removing them when idle?
> Amazon EC2 Auto Scaling.

> [!question]- Which load balancer type is designed for deploying third-party firewall appliances?
> Gateway Load Balancer.
