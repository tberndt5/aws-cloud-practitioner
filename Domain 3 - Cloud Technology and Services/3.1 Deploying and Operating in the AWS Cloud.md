# 3.1 Define methods of deploying and operating in the AWS Cloud

> [!abstract] Exam guide objective (verbatim from the CLF-C02 exam guide)
> **Knowledge of:**
> - Different ways of provisioning and operating in the AWS Cloud
> - Different ways to access AWS services
> - Types of cloud deployment models
> - Connectivity options
>
> **Skills in:**
> - Deciding between options such as programmatic access (for example, APIs, SDKs, CLI), the AWS Management Console, and infrastructure as code (IaC)
> - Evaluating requirements to determine whether to use one-time operations or repeatable processes
> - Identifying different deployment models (for example, cloud, hybrid, on-premises)
> - Identifying connectivity options (for example, AWS VPN, AWS Direct Connect, public internet)

## Big picture

This objective is about *how* you get things done in AWS: which tool you use to create and manage resources, which deployment model an organization is running, and how its network reaches AWS. Every action in AWS is ultimately an API call; the Management Console, the CLI, the SDKs, and CloudFormation are different front ends for those same APIs. Exam questions give a scenario ("a developer wants to call S3 from a Java app", "a team must create identical environments in three Regions", "a company needs a consistent private link to its data center") and ask you to pick the tool, the model, or the connection. The deciding words are usually *visual vs scripted*, *one-time vs repeatable*, and *internet vs private and consistent*.

## Key concepts

### Every access method uses the AWS APIs

An **API** (application programming interface) is the set of HTTPS requests that each AWS service exposes. Whatever you click or type is translated into these calls, which is why AWS CloudTrail can record "actions taken by users in the console, AWS CLI, AWS SDKs, and APIs" alike.

| Method | What it is | Best for | Signal words |
| --- | --- | --- | --- |
| **AWS Management Console** | "Web application used to manage AWS resources" (point and click in a browser) | Learning, exploring, one-off tasks, visual dashboards, billing views | "graphical", "web-based", "no code", "new user" |
| **AWS CLI** (Command Line Interface) | "Interact with AWS services through commands in the command-line shell" | Scripting and automating tasks from a terminal; repeating the same command | "terminal", "shell script", "command line", "automate from a script" |
| **AWS SDKs** (software development kits) | "Use software development kits to develop applications in your preferred programming language" (Java, Python, JavaScript, .NET, Go, and more) | Calling AWS from inside application code | "application code", "programming language", "developer integrates" |
| **AWS CloudShell** | "A browser-based, pre-authenticated shell that users can launch directly from the console" | Running CLI commands without installing anything or configuring credentials | "from the browser", "no local install", "pre-authenticated" |
| **Direct API calls** | Signed HTTPS requests to service endpoints | Rare; the SDKs and CLI do the signing and retries for you | "programmatic access" (umbrella term for CLI, SDK, API) |
| **Infrastructure as code (IaC)** with **AWS CloudFormation** | "Model, set up, and create templates of AWS resources" | Repeatable, version-controlled, consistent environments | "template", "repeatable", "consistent across environments/Regions", "provision as code" |

Programmatic access (CLI, SDK, API) authenticates with **access keys** (an access key ID plus a secret access key); the console uses a user name and password, ideally with MFA. See [[2.3 Access Management and IAM]].

CloudShell facts worth knowing: it opens with the credentials you used to sign in to the console, has the AWS CLI preinstalled, gives up to 1 GB of persistent home-directory storage per Region, and costs nothing extra (you pay only for resources you create).

### Infrastructure as code and AWS CloudFormation

**Infrastructure as code (IaC)** means describing your infrastructure in a text file and letting a service build it, instead of clicking through screens. In AWS CloudFormation:

- A **template** (JSON or YAML) declares the resources you want (VPC, EC2 instances, databases, IAM roles).
- CloudFormation creates them together as a **stack**, in the correct order, and can update or delete the whole stack as one unit.
- The same template deployed in another account or Region produces an identical environment. Templates can be stored in version control and reviewed like code.
- CloudFormation itself has no extra charge; you pay for the resources it creates.

Benefits the exam likes: ==repeatability, consistency, speed, fewer human errors, and easy rollback==. This also appears in Domain 1 as a benefit of automation ([[1.4 Cloud Economics]]).

**Where AWS Elastic Beanstalk fits:** Elastic Beanstalk is a platform-as-a-service. You upload application code (Java, .NET, PHP, Node.js, Python, Ruby, Go, Docker) and it provisions and manages the EC2 instances, load balancer, Auto Scaling, and monitoring for you. You can still see and control the underlying resources. It is about *deploying an application* quickly; CloudFormation is about *defining any infrastructure* precisely. Elastic Beanstalk has no extra charge either. Details in [[3.3 Compute Services]].

### One-time operations vs repeatable processes

| Requirement | Good choice | Why |
| --- | --- | --- |
| Explore a service, check a setting, a single change | Management Console | Fast, visual, no setup |
| A quick command without installing tools | CloudShell (or the CLI) | Pre-authenticated in the browser |
| The same task run regularly (nightly snapshot, user creation) | CLI scripts or SDK code | Scriptable and schedulable |
| Identical environments (dev, test, prod) or many Regions/accounts | CloudFormation (IaC) | Template guarantees the same result every time |
| Application needs to use AWS at runtime | SDK | Native to the programming language |

Rule of thumb: if a question says *repeatable*, *consistent*, *multiple environments*, *reduce manual errors*, or *version control*, the answer is infrastructure as code (CloudFormation). If it says *one time* or *quick check*, the console is fine.

### Cloud computing models: IaaS, PaaS, SaaS

AWS describes three service models, which differ in how much the provider manages:

| Model | AWS definition (paraphrased) | You manage | AWS examples |
| --- | --- | --- | --- |
| **IaaS** (infrastructure as a service) | Basic building blocks of cloud IT: networking, computers, storage. Most control. | OS, runtime, application, data | Amazon EC2, Amazon VPC, Amazon EBS |
| **PaaS** (platform as a service) | Provider removes the need to manage the underlying infrastructure; you focus on deploying and managing your application | Application code and data | AWS Elastic Beanstalk |
| **SaaS** (software as a service) | Complete software run and managed by the vendor; you just use it | Only your use of it and your data | Webmail, CRM; on AWS, end-user services such as Amazon Connect or Amazon WorkSpaces; third-party SaaS in AWS Marketplace |

The more managed the model, the more of the shared responsibility shifts to AWS ([[2.1 Shared Responsibility Model]]).

### Deployment models: cloud, hybrid, on-premises

| Model | Definition | Typical reason |
| --- | --- | --- |
| **Cloud** (cloud-native, "all-in") | All parts of the application run in the cloud | New applications, full use of managed services |
| **Hybrid** | Cloud resources connected to infrastructure that stays on premises | Gradual migration, legacy systems that must stay, data that must remain local, latency to on-site equipment |
| **On-premises** (private cloud) | Resources run in your own data center using virtualization and resource management tools; in most cases the same as legacy IT | Full control; AWS calls this "private cloud" |

**AWS Outposts** "extends AWS infrastructure, services, APIs, and tools to customer premises." AWS delivers, installs, and manages racks (or smaller servers) of AWS hardware in your data center, so you run services such as EC2, EBS, ECS, and RDS locally with the same console and APIs. Use it for a **hybrid** setup when workloads need very low latency to on-site systems, local data processing, or data residency on premises. AWS maintains the hardware; you are responsible for the physical security of the site where it sits. See [[Services - Compute#AWS Outposts|AWS Outposts]].

### Connectivity options (overview)

How an on-premises network or user reaches AWS. Network components (VPC, subnets, gateways) are covered in [[3.5 Network Services]].

| Option | What it is | Path | Strengths | Trade-offs |
| --- | --- | --- | --- | --- |
| **Public internet** | Reach public AWS endpoints over the internet (HTTPS) | Internet | Free to set up, immediate | Variable performance; not private |
| **AWS Site-to-Site VPN** | Encrypted IPsec tunnels between your on-premises network and a VPC | Over the internet | Quick to set up (minutes), low cost, encrypted | Performance depends on the internet |
| **AWS Client VPN** | Managed VPN for *individual users'* devices to reach AWS or on-premises networks | Over the internet | Remote workers, laptops | Per-user, not network-to-network |
| **AWS Direct Connect** | "A private dedicated network connection from an on-premises data center to the cloud" | Private line through a Direct Connect location, not the public internet | Consistent performance, high bandwidth, can lower data transfer cost | Takes weeks to provision; traffic is not encrypted by default |

Common combinations: Direct Connect as the primary link with a Site-to-Site VPN as a cheaper backup; or a VPN running over Direct Connect when encryption is required on the private line.

The reference guide one-liner for AWS VPN: "establish a secure and private tunnel from on premises to the cloud." On the AWS side a Site-to-Site VPN ends at a **virtual private gateway** (or transit gateway); on your side at a **customer gateway**. See [[Networking and Gateways]].

## Exam traps and commonly confused

> [!warning] CloudFormation vs Elastic Beanstalk
> CloudFormation = you describe **any** infrastructure in a template (IaC). Elastic Beanstalk = you hand over **application code** and it builds a standard web-app environment (PaaS). "Template" points to CloudFormation; "just upload the code" points to Elastic Beanstalk.

> [!warning] CLI vs SDK vs CloudShell
> CLI = commands in a terminal. SDK = libraries inside application code. CloudShell = a browser terminal that already has the CLI and your credentials. All three are "programmatic access".

> [!warning] Site-to-Site VPN vs Direct Connect
> VPN travels **over the public internet**, encrypted, set up in minutes. Direct Connect is a **private, dedicated** line, consistent performance, takes weeks, and is **not encrypted by default**. "Fastest to set up" or "lowest cost" points to VPN; "consistent network performance" or "does not traverse the internet" points to Direct Connect.

> [!warning] Site-to-Site VPN vs Client VPN
> Site-to-Site connects a whole **network** (an office or data center). Client VPN connects **individual users** on their devices.

> [!warning] Outposts vs Local Zones vs Wavelength
> Outposts is in **your** building. Local Zones are AWS-run sites near large cities. Wavelength is inside **telecom 5G** networks. See [[3.2 AWS Global Infrastructure]].

> [!warning] "On-premises" deployment model
> AWS also calls on-premises deployment **private cloud**. Hybrid is the mix of cloud and on premises, not "two cloud providers".

## Quick self-check

> [!question]- A team must create identical dev, test, and production environments in two Regions and keep the definitions in version control. What should they use?
> AWS CloudFormation (infrastructure as code) templates.

> [!question]- A developer wants a Python application to upload files to Amazon S3. Which access method fits?
> The AWS SDK for Python (an AWS SDK).

> [!question]- An administrator wants to run AWS CLI commands from a browser without installing anything or configuring keys. Which service?
> AWS CloudShell.

> [!question]- Which deployment model keeps some workloads in the company data center and connects them to workloads in AWS?
> Hybrid.

> [!question]- What does AWS Outposts provide?
> AWS-managed infrastructure, services, APIs, and tools installed at the customer's premises.

> [!question]- Which connectivity option gives a private, dedicated connection with consistent performance that does not use the public internet?
> AWS Direct Connect.

> [!question]- A company needs an encrypted connection from its office network to a VPC this week at low cost. What fits?
> AWS Site-to-Site VPN.

> [!question]- Which cloud service model gives the customer the most control over the operating system?
> IaaS (for example, Amazon EC2).

> [!question]- Which service lets a developer upload a web application's code and have AWS provision the servers, load balancer, and scaling?
> AWS Elastic Beanstalk.
