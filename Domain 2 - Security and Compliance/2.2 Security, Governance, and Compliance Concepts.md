# 2.2 Understand AWS Cloud security, governance, and compliance concepts

> [!abstract] Exam guide objective (verbatim from the CLF-C02 exam guide)
> **Knowledge of:**
> - AWS compliance and governance concepts
> - Benefits of cloud security (for example, encryption)
> - Where to capture and locate logs that are associated with cloud security
>
> **Skills in:**
> - Identifying where to find AWS compliance information (for example, AWS Artifact)
> - Understanding compliance needs among geographic locations or industries (for example, AWS Compliance)
> - Describing how customers secure resources on AWS (for example, Amazon Inspector, AWS Security Hub, Amazon GuardDuty, AWS Shield)
> - Identifying different encryption options (for example, encryption in transit, encryption at rest)
> - Recognizing services that aid in governance and compliance (for example, monitoring with Amazon CloudWatch; auditing with AWS CloudTrail, AWS Audit Manager, and AWS Config; reporting with access reports)
> - Recognizing compliance requirements that vary among AWS services

## Big picture

This objective is about proving and maintaining a secure, compliant environment. You need to know where AWS publishes its compliance evidence (AWS Artifact and the AWS Compliance programs site), how encryption protects data at rest and in transit, which service records which kind of log, and which security service detects which kind of problem. Most questions are "which service" scenarios: a phrase like "who made this API call" points to CloudTrail, "download a SOC 2 report" points to Artifact, "find PII in S3" points to Macie. Learn the distinguishing cue for each look-alike service and this objective becomes easy points.

## Key concepts

### Compliance and governance: definitions

- **Compliance:** meeting the requirements of a law, regulation, or industry standard (for example HIPAA for US health data, PCI DSS for payment card data, GDPR for EU personal data).
- **Governance:** the rules, controls, and oversight an organization uses to manage its environment (who can do what, which resources are allowed, how changes are tracked).
- **Audit:** collecting evidence that controls work. AWS provides evidence for its side; customers collect evidence for their side.

### Where to find AWS compliance information

- **[[Services - Security, Identity, and Compliance#AWS Artifact|AWS Artifact]]:** a free, self-service portal in the console for **on-demand access to AWS security and compliance documents**.
  - **Artifact Reports:** third-party audit reports on AWS, such as SOC 1, SOC 2, SOC 3, ISO certifications, and PCI DSS attestations of compliance. You give these to your auditors as evidence of AWS's controls.
  - **Artifact Agreements:** review, accept, and manage agreements with AWS, such as the Business Associate Addendum (BAA) needed for HIPAA, for one account or for all accounts in an organization.
- **AWS Compliance (aws.amazon.com/compliance):** the AWS website that explains the compliance programs AWS participates in, grouped by **global, regional (geographic), and industry** requirements. Examples: ISO 27001 (global), SOC (global), PCI DSS (payments industry), HIPAA (US healthcare), FedRAMP (US government), GDPR (European Union), C5 (Germany), IRAP (Australia).
- **AWS Services in Scope by Compliance Program:** a page that lists which AWS services are covered by each program. ==Compliance requirements vary among AWS services: not every service is in scope for every program==, so a regulated workload must use services that are in scope for its program (for example, HIPAA-eligible services).

> [!note] Compliance is still shared
> AWS being certified for a program does not make the customer's workload compliant. AWS's audited controls are **inherited**; the customer must still configure and operate their own workload to meet the requirement. Data residency is a customer choice: data stays in the Region the customer selects, which helps meet geographic laws.

### Benefits of cloud security

- AWS infrastructure is built to meet the requirements of very security-sensitive organizations, and customers inherit those controls instead of building their own data center security.
- Security services are API-driven and automatable, so checks can run continuously instead of at audit time.
- Encryption is built into most storage and database services, often with one setting, and keys can be managed centrally.
- Pay only for the security services you use; scale protection with the workload.

### Encryption: at rest vs in transit

- **Encryption at rest:** protects stored data (on disk, in a database, in a backup). Examples: S3 server-side encryption, EBS volume encryption, RDS encryption, DynamoDB encryption (on by default). Keys usually come from AWS KMS.
- **Encryption in transit:** protects data moving across a network, using TLS (the protocol behind HTTPS), or IPsec for AWS Site-to-Site VPN. Certificates for TLS come from AWS Certificate Manager.
- **Client-side encryption:** the customer encrypts data before sending it to AWS, and manages the keys. A customer responsibility.
- **Server-side encryption:** the AWS service encrypts the data when it writes it and decrypts it when it is read.

| Service | Role in encryption | Cue |
| --- | --- | --- |
| [[Services - Security, Identity, and Compliance#AWS Key Management Service (AWS KMS)\|AWS KMS]] | Create, manage, and control encryption keys; integrated with most AWS services; every key use is logged in CloudTrail | "Managed encryption keys", "at rest", "key rotation", "integrated with S3/EBS/RDS" |
| [[Services - Security, Identity, and Compliance#AWS CloudHSM\|AWS CloudHSM]] | Dedicated, single-tenant hardware security module (HSM) in your VPC; you alone manage the keys; AWS cannot recover them | "Dedicated HSM", "single-tenant", "full control of keys", "FIPS 140-2 Level 3" |
| [[Services - Security, Identity, and Compliance#AWS Certificate Manager (ACM)\|AWS Certificate Manager (ACM)]] | Provision, store, and automatically renew public and private SSL/TLS certificates | "HTTPS", "TLS certificate", "in transit", "certificate renewal" |
| [[Services - Storage#Amazon S3\|Amazon S3]] server-side encryption | SSE-S3 (Amazon S3 managed keys, the default for new objects since January 2023), SSE-KMS (keys in KMS, with audit trail and control), DSSE-KMS (dual-layer with KMS), SSE-C (customer provides the key with each request) | "Encrypt objects at rest in S3" |

Current status: the CloudHSM FAQ says CloudHSM provides FIPS 140-2 Level 3 validated HSMs and that the newer hsm2m.medium HSMs are FIPS 140-3 Level 3 certified.

> [!tip] KMS vs CloudHSM in one line
> KMS = AWS-managed, multi-tenant key service, easiest, integrated everywhere. CloudHSM = your own dedicated HSM, single-tenant, you manage the keys and the HSM users.

### Where logs live

| Log source | What it records | Where it is stored or viewed |
| --- | --- | --- |
| [[Services - Management and Governance#AWS CloudTrail\|AWS CloudTrail]] | **API activity**: who did what, when, from where, in the console, CLI, SDKs, and APIs | Event history shows the last **90 days** of management events in the console by default; create a **trail** to deliver logs to an S3 bucket (and optionally CloudWatch Logs) for long-term retention |
| [[Services - Management and Governance#Amazon CloudWatch\|Amazon CloudWatch]] Logs | Application, OS, and service log files (for example Lambda function logs, EC2 logs via the CloudWatch agent) | CloudWatch Logs log groups; search, metric filters, alarms |
| [[Services - Management and Governance#AWS Config\|AWS Config]] | **Configuration history** of resources and compliance against rules | Configuration items and snapshots delivered to an S3 bucket; timeline in the Config console |
| VPC Flow Logs (feature of [[Services - Networking and Content Delivery#Amazon VPC\|Amazon VPC]]) | IP traffic metadata going to and from network interfaces in a VPC (source, destination, port, accept or reject) | Published to CloudWatch Logs, S3, or Amazon Data Firehose |
| S3 server access logs | Detailed records of requests made to an S3 bucket | Delivered to another S3 bucket you choose |
| Load balancer access logs, CloudFront logs | Requests to the load balancer or distribution | S3 |

Mnemonic: **CloudTrail = Trail of who did what (API calls). CloudWatch = Watch performance (metrics, logs, alarms). Config = Configuration history and compliance rules.**

### Governance and compliance services: monitor, audit, report

The exam guide groups these as monitoring (CloudWatch), auditing (CloudTrail, Audit Manager, Config), and reporting (access reports).

| Service | Question it answers | Typical cue |
| --- | --- | --- |
| [[Services - Management and Governance#Amazon CloudWatch\|Amazon CloudWatch]] | How are my resources and applications performing? | Metrics, alarms, dashboards, CPU utilization, log monitoring |
| [[Services - Management and Governance#AWS CloudTrail\|AWS CloudTrail]] | Who made which API call, and when? | "Who deleted the bucket", "user activity", "audit API calls", "governance and auditing of the account" |
| [[Services - Management and Governance#AWS Config\|AWS Config]] | What did this resource look like before, what changed, and does it comply with my rules? | "Configuration history", "track changes", "evaluate resources against desired configuration", "is encryption enabled on every volume" |
| [[Services - Security, Identity, and Compliance#AWS Audit Manager\|AWS Audit Manager]] | Am I collecting evidence for my audit? | "Continuously audit usage", "automate evidence collection", "prebuilt frameworks such as PCI DSS, HIPAA, GDPR", "prepare for an audit" |
| Access reports | Who has which credentials and permissions, and are they used? | IAM credential report (all users and the status of their passwords, access keys, and MFA), IAM access advisor / last accessed information (which services a principal used and when), IAM Access Analyzer (resources shared outside your account or organization), AWS Organizations access reports |

Related governance services, covered by other notes: [[Services - Management and Governance#AWS Organizations|AWS Organizations]] (service control policies, central management of accounts), [[Services - Management and Governance#AWS Control Tower|AWS Control Tower]] (multi-account landing zone with guardrails), [[Services - Management and Governance#AWS Service Catalog|AWS Service Catalog]] (approved products), [[Services - Management and Governance#AWS Trusted Advisor|AWS Trusted Advisor]] (best-practice checks, see [[2.4 Security Components and Resources]]).

### How customers secure resources: detection and protection services

| Service | What it does | Data it looks at | Cue |
| --- | --- | --- | --- |
| [[Services - Security, Identity, and Compliance#Amazon GuardDuty\|Amazon GuardDuty]] | Intelligent **threat detection** with continuous monitoring, using machine learning and threat intelligence | CloudTrail events, VPC Flow Logs, DNS logs (plus optional sources such as S3 data events and EKS audit logs) | "Malicious activity", "compromised instance", "crypto mining", "unusual API calls", "threat detection" |
| [[Services - Security, Identity, and Compliance#Amazon Inspector\|Amazon Inspector]] | Automated **vulnerability scanning** | EC2 instances, container images in Amazon ECR, Lambda functions | "Software vulnerabilities (CVEs)", "unintended network exposure", "scan workloads" |
| [[Services - Security, Identity, and Compliance#Amazon Macie\|Amazon Macie]] | Discover and protect **sensitive data** using ML and pattern matching | Amazon S3 | "PII", "sensitive data in S3", "credit card numbers in buckets" |
| [[Services - Security, Identity, and Compliance#Amazon Detective\|Amazon Detective]] | **Investigate** and find the **root cause** of findings | Log data and findings (CloudTrail, VPC Flow Logs, GuardDuty) organized in a behavior graph | "Root cause", "investigate a finding", "analyze suspicious activity" |
| [[Services - Security, Identity, and Compliance#AWS Security Hub\|AWS Security Hub]] | **Central view** of security findings and posture checks across accounts | Findings from GuardDuty, Inspector, Macie, Firewall Manager, partner tools; automated checks against standards such as CIS and AWS Foundational Security Best Practices | "Single dashboard", "aggregate findings", "prioritize security issues across accounts" |
| [[Services - Security, Identity, and Compliance#AWS Shield\|AWS Shield]] | **DDoS protection** | Network and transport layer traffic (Advanced adds application layer) | "DDoS" |

Mnemonic for the detectors: **GuardDuty guards (threats), Inspector inspects (vulnerabilities), Macie finds PII in S3, Detective detects root cause, Security Hub is the hub (aggregates).**

Shield, WAF, Firewall Manager, Network Firewall, security groups, and NACLs are compared in [[2.4 Security Components and Resources]]. Quick recap: Shield Standard is automatic and free for all customers; Shield Advanced is a paid subscription with extra DDoS protection and a response team.

## Exam traps and commonly confused

> [!warning] CloudTrail vs CloudWatch vs Config
> CloudTrail records **who did what** (API calls). CloudWatch measures **how it is performing** (metrics, alarms, logs). Config records **what the resource looks like and how it changed**, and checks it against rules. "Who changed the security group" = CloudTrail. "What did the security group look like last Tuesday" = Config.

> [!warning] AWS Artifact vs AWS Audit Manager
> Artifact gives you **AWS's** compliance reports (evidence about AWS). Audit Manager collects evidence about **your own** AWS usage for your audits.

> [!warning] AWS Config vs Audit Manager
> Config evaluates resource configurations against rules. Audit Manager maps evidence (including Config results) to compliance frameworks and produces audit-ready reports.

> [!warning] GuardDuty vs Inspector
> GuardDuty watches activity for **threats** (logs-based, no agents needed). Inspector scans workloads for **vulnerabilities** (software CVEs and network reachability).

> [!warning] Macie vs GuardDuty
> Both use machine learning. Macie is about **sensitive data in S3**. GuardDuty is about **malicious activity** across the account.

> [!warning] Detective vs Security Hub
> Security Hub **collects and prioritizes** findings. Detective **investigates** a finding to its root cause.

> [!warning] KMS vs CloudHSM vs ACM
> KMS and CloudHSM manage encryption keys (at rest). ACM manages TLS certificates (in transit). Single-tenant or dedicated hardware = CloudHSM.

> [!warning] AWS compliance does not equal customer compliance
> A service being HIPAA-eligible or PCI-compliant does not make your application compliant. You must configure it correctly; check the Services in Scope page because coverage varies by service.

## Quick self-check

> [!question]- An auditor asks for AWS's SOC 2 report. Where does the customer get it?
> AWS Artifact (Artifact Reports).

> [!question]- Which service shows which IAM user terminated an EC2 instance yesterday?
> AWS CloudTrail.

> [!question]- Which service keeps a history of a resource's configuration and evaluates it against rules?
> AWS Config.

> [!question]- Which service discovers personally identifiable information stored in Amazon S3?
> Amazon Macie.

> [!question]- Which service scans EC2 instances and container images for software vulnerabilities?
> Amazon Inspector.

> [!question]- Which service detects a compromised EC2 instance communicating with a known malicious IP address?
> Amazon GuardDuty.

> [!question]- Which service gives one dashboard of prioritized findings from GuardDuty, Inspector, and Macie across accounts?
> AWS Security Hub.

> [!question]- What is the difference between encryption at rest and in transit, with one AWS service for each?
> At rest protects stored data (AWS KMS keys for S3, EBS, RDS). In transit protects data moving over the network with TLS (AWS Certificate Manager certificates).

> [!question]- Where do VPC Flow Logs get published?
> Amazon CloudWatch Logs, Amazon S3, or Amazon Data Firehose.

> [!question]- Which service automates evidence collection to prepare for a PCI DSS audit of your own workloads?
> AWS Audit Manager.
